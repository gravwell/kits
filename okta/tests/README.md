# Okta kit detection tests

`okta_fixtures.py` is a regression test for every detection in the kit, built from
synthetic Okta System Log events. Nothing here is real data: users are `@example.com`, IPs
come from the documentation ranges (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24), and IDs
are hashes of the case name.

Each case is a few events placed in its own 15-minute window (case N = 2026-01-05 00:00 UTC
+ N hours, minutes 00-15), the same window shape as the kit's scheduled searches. History
that a detection looks back on (an account created 2 hours earlier, a deactivation 3 days
earlier) sits at minute 35 of an earlier hour, outside every case window. A case lists the
detections that must fire in its window. Every other detection must stay silent there, so
the test catches missed detections and detections firing on the wrong events. Cases ending
in `-below-threshold`, `known-ip`, `harmless-scope`, `reactivation`, `same-ip` and
`mobile-session` check that a detection does not fire.

`fixtures.jsonl` is generated by `build` and committed so the events can be read without
running anything. Edit the cases in the script, not the JSONL.

## Running

The kit must be installed on the instance (the check reads the queries from this
directory, but the server expands the kit's macros and lookups).

```bash
export GRAVWELL_URL=http://gravwell GRAVWELL_TOKEN=...   # token with search + ingest
python3 okta_fixtures.py list                 # cases and their windows
python3 okta_fixtures.py build                # regenerate fixtures.jsonl
python3 okta_fixtures.py ingest               # import into tag okta-fixtures (once per tag)
python3 okta_fixtures.py check                # about 2 minutes
python3 okta_fixtures.py check --full         # every detection on every case window, about an hour
python3 okta_fixtures.py check admin-console-new-ip   # selected cases
```

`check` substitutes `okta-fixtures` for `$OKTA_SYSTEM` in each detection, including inside
kit macros that refer to it. It runs in two passes: first each detection once over the whole
fixture span, mapping result rows to cases by their `published` time; then each
(case, detection) pair that fired or is expected, on the exact 15-minute window. This
relies on a detection that fires on a case's window also firing for that case over the
whole span. That holds for the current rules, because cases don't share users, IPs or
devices, but nothing enforces it for a new rule. After changing detection logic, run
`--full`, which checks every pair directly.

Re-importing the same file duplicates every event, and the "below threshold" cases would
then fire. After changing the fixtures, ingest into a new tag and point both commands at
it: `OKTA_FIXTURE_TAG=okta-fixtures2 python3 okta_fixtures.py ingest` (and `check`).

The last run: 58/58 cases pass, 0 query errors, 49/49 detections covered, both with the
default check and with `--full` (all 2,842 case and detection pairs, about an hour on a small
instance that is also running the kit's scheduled searches).
